# CafeFocus — 카페 작업환경 지도

[![CI](https://github.com/sanghohoho0813-lab/sample7-Cafefocus-map-mvp/actions/workflows/ci.yml/badge.svg?branch=claude/cafefocus-map-mvp-nqs0vx)](https://github.com/sanghohoho0813-lab/sample7-Cafefocus-map-mvp/actions/workflows/ci.yml)

**"오늘 어디서, 언제, 얼마나 작업할까?"를 실제로 정해주는 도구**

카페를 검색해 보여주는 데서 끝나지 않고, 지역·작업 목적·갈 시간 세 가지만 고르면 **가장 잘 맞는 한 곳과 그 이유**를 먼저 보여주고,
**작업 계획 → 다녀온 뒤 체크인 → 내 기록이 다음 추천에 반영**되는 흐름까지 이어지는 반응형 웹앱입니다.
미래AI랩 샘플로, 외부 API 키 없이 결정적(deterministic) 데모 데이터로 동작합니다.

Next.js 15 (App Router) · React 19 · TypeScript strict · Tailwind CSS · Vitest · Playwright · axe-core

## 빠르게 시작

```bash
npm install
npm run dev          # http://localhost:3000
```

| 명령 | 내용 |
| --- | --- |
| `npm run build` / `start` | 프로덕션 빌드 · 실행 (79개 경로 정적 생성, Vercel 배포 가능) |
| `npm run lint` | ESLint (next/core-web-vitals + next/typescript) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | 단위 테스트 (Vitest) |
| `npm run test:e2e` | E2E · 접근성 테스트 (Playwright, 프로덕션 빌드 필요) |
| `npm run check` | lint + typecheck + 단위 테스트 한 번에 |

환경 변수는 하나뿐입니다. `NEXT_PUBLIC_SITE_URL` — OG 이미지·사이트맵의 절대 주소 (Vercel에서는 자동).

## 핵심 흐름

1. **지도** `/` — 첫 화면에는 **어디서 · 무엇을 · 언제** 세 가지만. 세부 조건(콘센트·조용함 등)은 "조건" 시트에서 필요할 때 더하고, 적용된 조건은 칩으로 바로 뺄 수 있음.
   목록 맨 위에 "지금 가장 잘 맞는 곳" 한 장(이유 2개 + 주의 1개 + "N시에 작업하기"), 그 아래 다른 후보.
   마커 ↔ 카드 선택·강조·스크롤 동기화, 카드의 위치 버튼으로 모바일 시트를 내리고 마커로 이동. 다음 작업은 지도 위 칩과 마커에 표시
2. **상세** `/cafe/[id]` — **결론 → 이유(✓) → 주의점(!) → 시간대 비교 → 체크인 요약 → 상세 정보 → 계획** 순서.
   "왜 83점인가요?"를 열면 항목별 점수·목적별 비중·체류 시간 보정이 그대로 보임. 시간대 비교는 지금 · 내가 고른 시간 · 가장 추천을 한 줄로
3. **계획** `/cafe/[id]/plan` — 언제(날짜·도착 시간, 추천 시간 표시) · 얼마나(마감까지 남은 시간 안내) · 무엇을(목적·할 일).
   지난 시간·영업 외·마감 초과·다른 계획과 겹침은 고르기 전부터 막힘
4. **계획 확인** `/plans/[id]` — 도착 전 알아둘 점(이유·주의·더 나은 시간). 지도 마커·상단 칩·내 작업에 즉시 반영
5. **체크인** `/cafe/[id]/review?plan=` — 작업 만족도 + 소음·콘센트·Wi-Fi·좌석 → 계획 완료, 상세의 체크인 요약과 내 작업 패턴에 반영
6. **내 작업** `/my` — 예정·지난 기록, 최근 7일 작업 시간, **내 작업 패턴**(자주 가는 지역·주로 하는 작업·보통 머무는 시간·만족했던 조건)

보조 화면: `/recommend`(3단계 맞춤 추천), `/favorites`(저장 → 비교 담기), `/compare`(2~3곳 비교 + 결론).

## 설계에서 신경 쓴 것

**주소가 곧 상태** — 지도의 지역·목적·시간·필터·선택한 카페는 쿼리스트링에 담깁니다
(`/?area=seongsu&p=study&t=15&f=outlet,quiet&cafe=workroom-17`). 새로고침·공유·뒤로가기에도 같은 화면이 나오고,
손으로 고친 잘못된 값은 조용히 버립니다. `history.replaceState`를 써서 조건을 바꿀 때마다 기록이 쌓이지 않습니다.
→ `lib/exploreQuery.ts`

**하이드레이션 안전** — 서버 HTML에는 현재 시각을 쓰지 않습니다. `useNow()`는 마운트 전 `null`을 돌려주고,
그동안은 고정 기준 시각(15시)과 자리표시를 그려 서버·클라이언트 마크업이 항상 일치합니다. → `lib/useNow.ts`, `lib/time.ts`

**깨지지 않는 저장소** — localStorage 값은 읽을 때 항목 단위로 검증합니다. 사용자가 값을 고치거나 이전 버전 데이터가 남아 있어도
손상된 항목만 버리고 나머지 기록은 유지하며, 점수 계산을 망가뜨릴 수 있는 잘못된 목적 값은 기본값으로 되돌립니다.
시크릿 모드처럼 저장소를 쓸 수 없으면 메모리 상태로 동작합니다. → `lib/storage.ts`

**규칙은 한 곳에서** — 계획 검증(영업 시간·지난 시간·마감 초과·겹침)은 `validatePlan` 하나를 폼의 실시간 안내와
저장 직전 가드가 같이 씁니다. 빠른 더블클릭에도 계획이 두 번 생기지 않도록 동기 ref로 막습니다. → `lib/plans.ts`, `lib/store.tsx`

**설명 가능한 점수** — 적합도는 예측 모델이 아닌 규칙 기반 가중합이고, 화면에 "규칙 기반 · 데모 예측값"을 밝힙니다.
목적별 가중치(합 1.0) × 항목 점수에, 소음·혼잡은 **머무는 시간 동안의 평균**(도착 시각 가중 2배)을 씁니다.
마감 전에 나가야 하면 감점, 오래 머물기 좋은 곳은 가점. `explainFit()` 하나가 점수와 함께
조건별 이유("지금 조용한 편", "2시간 이상 작업에 적합", "콘센트 충분")와 주의점("15시 이후 혼잡 예상", "22:00 마감 · 1시간만 가능")을 만들고,
카드·미리보기·상세·계획이 모두 같은 결과를 씁니다. `bestHour()`는 남은 시간 중 가장 좋은 도착 시각을,
`decision()`은 "지금 가기 좋아요 / 갈 만해요 / 추천하지 않아요" 결론을 냅니다.
데이터가 없는 새벽·심야에는 가장 가까운 시간으로 보정하고 "21시 기준"처럼 표기합니다. → `lib/fit.ts`

**내 기록으로 맞춤** — 별도 모델 없이 사용자가 남긴 계획·체크인만 집계합니다(`habitsFrom`). 완료·예정 작업이 2건 이상이면
점수의 체류 시간을 "보통 머무는 시간"으로 바꾸고 화면에 "내 기록 반영"이라고 밝힙니다. 자주 가는 지역은 한 번에 좁혀 볼 수 있게 제안하고,
카드에는 "지난번 ★5" · "자주 가는 지역"처럼 근거가 보이는 한 줄만 붙입니다. → `lib/personal.ts`, `lib/useFitContext.ts`

**체크인 요약** — 별점 대신 "조용했어요 · 콘센트를 쉽게 찾았어요 · Wi-Fi가 빨랐어요 · 좌석이 편했어요" 응답 비율과 작업 만족도로 보여주고,
내 체크인은 바로 합산합니다. → `lib/reviews.ts`

**접근성** — 모든 화면과 열린 시트를 axe(WCAG 2.1 AA)로 검사해 위반 0건을 CI에서 유지합니다. 보조 글자색도 모든 배경에서 4.5:1 이상,
본문 건너뛰기 링크, 시트의 포커스 가두기·복귀, 키보드 단축키(`/` 검색, `Esc` 선택 해제), 핀치 줌 허용,
`prefers-reduced-motion` 존중.

**데모 데이터의 정직함** — 카페 22곳과 시간대 데이터는 고정 시드입니다. 첫 방문 시 샘플 계정(최근 완료한 작업 2건·체크인 2건)이
**오늘 기준 상대 날짜**로 채워지고, `내 작업 → 데모 데이터 초기화`로 언제든 되돌릴 수 있습니다.
시드에는 버전이 있어(`cf:seed-version`) 이전 버전 사용자는 기존 기록을 지우지 않고 빠진 샘플만 더해집니다.

## 테스트

```
tests/
  unit/   Vitest — 시간·계획 검증·적합도 엔진·이유/주의/결론·추천 시간·내 작업 패턴·필터·추천·URL 상태·저장소 (67개)
  e2e/    Playwright — 골든 패스(지도→상세→계획→체크인), 상세 순서·점수 근거, 계획→지도 반영, 시간 겹침, URL 상태,
          검색·섹션 바로가기·목록 정렬·비교·체크인 진행·공유·404, axe 접근성(검색 열림·상세 머리글·비교 결과 등 열린 상태 포함)
          (모바일·데스크톱 2개 프로젝트, 71개)
```

E2E는 시계를 화요일 14:10(서울)으로 고정하고 외부 요청을 막아 결과가 항상 같습니다.
CI(GitHub Actions)는 lint → typecheck → 단위 테스트 → 빌드 → E2E 순서로 돌고, 실패하면 Playwright 리포트와 trace를 남깁니다.

브라우저가 미리 설치된 환경에서는 `PW_CHROMIUM_PATH=/path/to/chromium npm run test:e2e`로 실행 파일을 지정할 수 있습니다.

## 디자인 원칙

화면 목적에 따라 비중을 달리한 **하이브리드** 구성입니다 — 고르는 화면(지도·상세 위쪽·저장)은 공간 사진이 이끌고,
정하는 화면(계획·체크인)은 단계와 입력이 이끕니다.

- 색: coffee(주색) + forest(좋음 강조 하나) + cream(중립) + amber(주의). 메뉴별 색 없음.
  주의 문구는 대비 4.5:1 이상의 `amber2-600`, 장식·아이콘만 `amber2-500`
- 글자: 역할별 스케일(`caption 13 / meta 14 / body 16 / title 18 / section 21 / page 26 / display 30 / score 30`),
  제목은 크기에 비례해 자간을 살짝 좁힘
- 한 화면에 주 행동 하나. 결론 → 이유 → 다음 행동 순서. 강조색은 "가장 좋은 것" 하나에만
- 지도: 바탕은 낮은 대비로 물러나고 마커(점수)가 먼저 읽힘. 모바일은 지도 아래 가로 카드를 넘기면 그 마커가 선택되고,
  마커를 누르면 그 카드로 넘어감
- 상세: 사진을 크게 → 본문 시트가 사진 위로 겹쳐 올라옴(모바일) / 사진 위에 이름(데스크톱). 하단 버튼에 행동과 점수를 함께
- 모바일 섹션은 10px 띠로 구분(계획·체크인·상세), 완료 화면은 티켓 + 진행 단계(계획 → 작업 → 체크인)
- 상호작용: 지도 목록 시트는 손가락을 따라 움직이고 놓으면 가까운 단계로 붙음(빠르게 튕기면 한 단계씩) ·
  상세는 사진이 지나가면 작은 머리글과 섹션 바로가기(결론·시간대·체크인·정보, 스크롤 위치에 따라 표시) ·
  모바일 검색은 전체 화면(지역 바로가기 · 최근 본 카페 · 사진과 점수가 있는 결과) ·
  체크인을 마치면 내 작업 패턴에 무엇이 반영됐는지 보여줌 · 모바일 알림은 위에서 내려옴(아래 버튼들과 겹치지 않게)
- 고르기 돕기: 지도 목록·저장 목록 정렬(추천순·가까운순·한산한순 / 적합도순·가까운순·최근 저장순, 마커는 그대로) ·
  가장 잘 맞는 곳 마커에 왕관 · 비교는 세 칸 + 항목별 막대(길수록 작업하기 좋음) · 추천 결과는 순위와 1·2위 점수 차이를 그대로 보여줌
- 작은 상호작용: 팝업 시트는 아래로 끌어 닫기 · 상세 링크 공유(휴대폰 공유 창 / 링크 복사) · 체크인 남은 항목 수와 진행 막대 ·
  화면 전환 페이드 · 하단 탭 활성 표시와 배지 반영 애니메이션 · 화면 모양 그대로의 로딩 자리표시 · 길을 안내하는 404·오류 화면
- 제작사 표시는 상단 한 줄 바와 파비콘. 외부 상담 CTA는 핵심 흐름을 마친 뒤에만

## 카페 사진

`/public/images/cafes/`에 22곳의 사진이 있습니다 — `{id}.webp`(1440×810, 상세) · `{id}-card.webp`(720×540, 카드).
`next/image`로 서빙하며 로딩 중에는 원본에서 만든 blur placeholder가 보입니다. 사진을 바꿀 때는 파일명을 카페 id와 맞춘 뒤
아래를 실행하고, 출력된 blur 맵을 `lib/data/cafes.ts`의 `BLUR`에 반영하세요.

```bash
node scripts/optimize-images.js <원본디렉터리>
```
